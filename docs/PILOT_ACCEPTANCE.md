# AgentReady v0.2 — 真实用户试点与验收标准

## 目标

从“开发者原型”走到“别人也能安全使用”。找两个自愿测试者：

1. **开发者**：已有 Codex/Claude/Hermes 之一，且已有本地或云端服务。
2. **普通使用者**：只有 Mac/iPhone + 日历/提醒事项，没有 Docker、SSH 和服务端部署经验。

禁止收集账号密码、聊天正文、密钥和公司资料作为调研数据；只保留受试者同意分享的脱敏结果。

## 测试路线

| 关卡 | 用户实际操作 | 验收标准 |
| --- | --- | --- |
| T0 | 从 ZIP/仓库打开项目 | 能找到中文说明、识别软件前置条件 |
| T1 | `doctor` + `coverage` | 已装/未检测/未验证严格区分，且不联网 |
| T2 | `wizard` 选择软件 | 可保存非敏感 JSON；重复文件被拒绝覆盖 |
| T3 | `plan` + `install` 不带 `--apply` | 只预览，无软件安装或全局配置修改 |
| T4 | 用户批准后分组安装 | Mac 上只安装清单内缺失项目；失败可诊断/重试 |
| T5 | `permissions` | 能清楚知道需要本人授权什么，不强制开启录屏 |
| T6 | 支持的原生服务探测 | 明确区分 HTTP、鉴权和 MCP 握手；没有读取业务行 |
| T7 | 原生应用任务路径 | 每个真实业务数据来源有唯一主应用，没有重复日程 |
| T8 | 用户复述下一步 | 能说出该打开哪个 App、尚有什么连接缺口 |

## 记录内容（脱敏）

- 操作系统与 Agent 种类、选择的 profile；不要记录主机名/用户名。
- T0–T8 每个关卡的 `passed / failed / blocked / not_tested`。
- 步骤是否需要多次登录/重复权限申请、明显卡顿和错误提示是否可理解。
- 只提供已获授权的截图，不截个人消息、日历内容或公司的保密信息。
- 记录真实耗时可帮助优化，但不设虚构性能目标。

## v0.3 最重要的缺口

优先推进一个 **真实的业务工作流** 而非增加一堆产品名称。建议选择“Apple Reminders/日历 → AI 每日简报”或“已授权 Feishu 任务 → 当日计划”，并实际验证登录、限范围读取、去重、回源链接和失败提示。第二步才是批量授权流程和跨操作系统安装。
